도구 선택 기준

작업 범위가 넓거나 실배포 환경에서 검증하며 버그를 찾아야 하는 단계는 Model 1(대화를 이어가며 붙잡고 있는 방식)에게 맡기고, "건드리면 안 되는 부분"까지 구체적으로 적은 인계 문서로 범위가 한 덩어리로 좁혀진 다음에만 Model 2(새 세션·새 모델)에게 넘긴다.

  1. 범위가 넓거나 실배포 환경 검증이 필요한 작업은 Model 1부터 쓰고, 범위가 한 덩어리로 좁혀지면 Model 2로 넘긴다.
  2. 인계 문서에 "건드리면 안 되는 부분"을 구체적으로 적으면 Model 2도 범위를 벗어나지 않는다 — 실제로 Model 2는 명시된 파일명 로직(+7/-3줄) 외 한 글자도 건드리지 않았다.
  3. 작업이 애매하면 Model 1을 유지하고, 같은 이유로 재작업이 2회 이상 반복되면 그때 잘게 쪼개 Model 2에게 넘긴다.

AI와 나의 판단

2026-08-25 원 작업 종료 시점에 작성해둔 AI 사용 기록 그대로입니다.

  • AI에게 맡긴 일 — PNG 다운로드 기능 구현, 실배포 후 발견된 도넛차트 버그 수정, 파일명 개선 기능의 설계·구현·인계 문서 작성을 Claude(AI A)에게, 파일명 중복 방지 코드 완성을 Gemini(AI B)에게 맡겼다.
  • 직접 판단한 일 — 실제 배포 페이지에서 직접 설문→계산→다운로드를 실행해 도넛차트 버그를 발견해 보고했고, Gemini의 결과가 인계 문서 범위를 벗어나지 않았는지 Claude에게 diff로 대조 검증하도록 확인했다. (재검증 단계에서는 검사 입력·기대값 표, 인계 문서 실행 명령 오류, 시간 상한 미기록, 판정표 이름 가림 등 빠진 항목을 무엇으로 보완할지도 직접 정했다.)
  • AI 제안을 따르지 않은 일 — 애초 계획은 Claude가 정상 케이스(검사 1–4)를 미완성으로 남기고 Gemini에게 넘기는 것이었지만, 실배포본에서 버그를 발견하자마자 Claude가 바로 수정하게 했고, 그 결과 Gemini에게 넘길 새 개선 과제(파일명 개선)를 별도로 다시 만들도록 요구했다.
